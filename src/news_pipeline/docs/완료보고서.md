# 뉴스 AI 파이프라인 — 완료 보고서

작성일: 2026-08-06

## 1. 개요

뉴스를 자동 수집(RSS/API/크롤링) → 정제 → AI 요약 → AI 인사이트 분석 → 시각화 → 리포트 → 내보내기까지 처리하는 CLI 기반 Python 애플리케이션을 `docs/../실행지시서`(대화 중 전달된 지시서) 기준으로 구현했습니다. 필수 기능과 보너스 기능(조회 CLI, 감성 분석, 스케줄링 문서화)을 모두 포함했습니다.

- 저장소: 로컬 git 저장소(`git init`), Phase 단위로 총 **14개 커밋**, 전부 한글 메시지
- GitHub 원격 저장소에는 아직 푸시하지 않음(요청대로 로컬 이력만 보존)

## 4. 실행 검증 근거 (최종 통합 테스트 기준)

```
fetch --source all --limit 6   → rss 6건 / api 6건 / crawl 6건 = 총 18건 (raw)
clean                          → raw 18건 중 신규 17건 저장, 중복 1건 스킵
summarize --unsummarized       → 누적 8건 요약 성공
sentiment --unanalyzed         → 누적 6건 감성 분류 성공
analyze --category IT          → 실제 Gemini 응답으로 트렌드/키워드/시사점 산출 및 저장
report --format md             → 정제율 94.4%, 요약완료율 47.1%, TOP5 카테고리, 차트 3종 포함 리포트 생성
export --format csv/excel      → csv 17건, excel(--status summarized) 8건 파일 생성
```

에러 케이스도 별도로 검증:
- 존재하지 않는 도메인으로 fetch → 3가지 수집 방식 모두 예외 없이 빈 리스트 반환 + 로그 기록
- `GEMINI_API_KEY` 미설정 상태로 summarize 호출 → 명확한 안내 메시지 후 종료(크래시 없음)

## 5. 알려진 제한사항

- **Gemini 무료 티어 쿼터**: 모델/계정에 따라 하루 요청 수가 제한됨(`docs/이슈노트.md` 5번 참고). 대량으로 `summarize`/`analyze`/`sentiment`를 돌리면 실패가 늘어날 수 있음 — `--limit`을 작게 잡고 나눠서 실행 권장.
- **위키백과 크롤링 소스**: "포털:최근 사건" 페이지는 하루 갱신량이 적어(테스트 시점 7건) 대량 수집에는 부적합. 학습/테스트 목적의 예시 소스로 등록한 것이며, 실제 서비스 시엔 `config add-source`로 다른 크롤링 대상을 추가하는 것을 권장.
- **published_at 정확도**: 위키백과 크롤링은 "N월 N일"처럼 연도가 없는 날짜 표기를 현재 연도로 보정해서 저장함 — 연말/연초 경계에서는 오차가 생길 수 있음.
- **날짜 필터(list/analyze 등)**: `published_at`의 앞 10자(YYYY-MM-DD)로 문자열 비교하므로, 매우 드물게 타임존 경계값에서 하루 오차가 있을 수 있음.

## 6. 실행 방법

`README.md`에 설치·초기 설정·전체 명령어·스케줄링 방법이 정리되어 있습니다. 요약하면:

```bash
python -m venv venv && venv\Scripts\activate
pip install -r requirements.txt
python main.py config set-api-key      # Gemini 키 등록
python main.py                          # 메뉴 모드로 바로 시작 가능
```
