# 코디세이(Codyssey) 로깅 시스템 적용 보고서

본 문서는 파이썬 기반 뉴스 데이터 파이프라인의 각 모듈에 적용된 로그 수준(Log Level)과 구체적인 적용 사유를 기록한 관리 문서입니다.

---

## 1. `automation.py`

- **모듈 역할**: 스케줄러(cron 등) 및 비대화형 CLI 실행 진입점
- **로그 적용 내역**:
  - `[INFO]` (run_cli): 스케줄러(자동화) 모드로 특정 작업이 정상적으로 시작되었음을 기록 (이력 추적용)
  - `[WARNING]` (run_cli): 사용자가 환경설정을 마치지 않은 상태에서 스케줄러 시간이 도래하여 빈 껍데기로 실행된 상황 (차단 및 경고)
  - `[ERROR]` (run_cli): 서브커맨드 미지정 또는 알 수 없는 명령어 입력. 이는 스케줄러(crontab)에 등록된 스크립트 작성 자체에 오타 등의 문제가 있다는 뜻이므로 관리자 조치 유도

## 2. `lib/dev/clean.py`

- **모듈 역할**: raw 데이터를 읽어 HTML 태그를 제거하고 규격을 통일하여 DB에 적재
- **로그 적용 내역**:
  - `[INFO]` (run_clean): 대용량 데이터 정제가 시작되었음을 알리고, 완료 후 처리 통계(저장, 제외, 스킵 건수)를 기록하여 파이프라인 수율을 모니터링
  - `[WARNING]` (run_clean): 스케줄러나 사용자가 실행을 지시했으나 저장된 raw 데이터가 없어 아무 작업도 하지 않고 건너뛴 상황 기록
  - `[ERROR]` (run_clean): 중복 정책(`policy`) 파라미터가 잘못 들어왔거나, 정제된 데이터를 최종적으로 DB에 Insert 하는 과정에서 권한/용량 등의 문제로 예외(Exception)가 발생한 경우

## 3. `lib/dev/fetch.py`

- **모듈 역할**: 외부 RSS 및 웹 크롤링을 통해 원본 뉴스 데이터(Raw Data) 수집 및 저장
- **로그 적용 내역**:
  - `[INFO]` (execute_fetch_logic): 수집 파이프라인의 시작과 끝을 기록하며, 각 소스별로 데이터를 몇 건이나 성공적으로 적재했는지 남겨 일일 수집량을 트래킹
  - `[WARNING]` (execute_fetch_logic): 지원하지 않는 수집 방식(API 등)이 호출되어 해당 소스를 건너뛰었거나, `--limit` 파라미터가 숫자가 아니어서 시스템 기본값(20건)으로 강제 보정된 경우
  - `[ERROR]` (execute_fetch_logic):
    - 1. 등록되지 않은 소스 이름을 요청하여 파이프라인이 즉시 중단된 경우
    - 2. 개별 뉴스 소스(RSS/HTML)의 네트워크 타임아웃, 404 에러, 구조 파싱 실패 등으로 수집이 실패한 경우 (관리자가 해당 URL의 유효성을 점검할 수 있도록 유도)

## 4. `lib/dev/summarize.py`

- **모듈 역할**: 정제된 뉴스(clean_news) 본문을 외부 AI API(Gemini, GPT 등)에 전송하여 3줄 요약 생성 후 DB에 적재
- **로그 적용 내역**:
  - `[INFO]` (run_summarize_unsummarized): 대량의 AI 요약 작업 시작 및 종료 시 처리 통계(대상/성공/실패)를 기록. 대기열에 미요약 기사가 없어 작업을 스킵한 일상적 상황도 기록
  - `[WARNING]` (run_summarize_cli): CLI 실행 시 `--limit` 값으로 음수나 문자열 등 비정상적인 값이 인입되어 기본값(10건)으로 보정 처리한 상황
  - `[ERROR]`:
    - 1. 시스템 전역에 AI API Key가 설정되지 않아 파이프라인 자체가 블록된 심각한 에러
    - 2. 개별 기사에 대한 AI 통신 실패(예: Quota Exceeded, 500 Server Error, Rate Limit 등). 이때 추적을 위해 에러 로그에 문제가 된 대상 기사의 고유 `news_id`를 함께 기록

## 5. `lib/dev/analyze.py`

- **모듈 역할**: 지정된 기간/분류의 뉴스들을 묶어 AI에게 전달한 뒤, 전체 트렌드와 키워드를 JSON 형태로 추출하여 저장
- **로그 적용 내역**:
  - `[INFO]` (run_analyze): 종합 분석 파이프라인의 시작과 성공적인 DB 적재를 기록하며, 분석할 기사가 없어 스킵된 상황도 함께 기록
  - `[WARNING]`:
    - 1. CLI 스크립트 작성 오류로 날짜 형식(YYYY-MM-DD)이 잘못 들어와 실행이 거부된 경우
    - 2. AI가 지시를 어기고 응답을 JSON이 아닌 일반 텍스트로 주어 파싱 에러가 발생, 2차 재시도(Retry) 로직이 발동한 경우 (프롬프트 튜닝의 지표로 활용)
  - `[ERROR]`: API Key 누락, AI 서버 응답 지연(Timeout), 또는 2번의 재시도에도 불구하고 JSON 파싱에 최종적으로 실패하여 분석이 완전히 무산된 심각한 상황

## 6. `lib/dev/sentiment.py`

- **모듈 역할**: 뉴스 본문/요약을 외부 AI에 전송하여 감성(긍정/부정/중립)을 분석하고 그 근거를 DB에 저장
- **로그 적용 내역**:
  - `[INFO]` (run_sentiment_analysis): 대량 감성 분석 처리 시작 및 성공/실패 통계, 혹은 조건에 맞는 대상이 없어 정상적으로 스킵된 상황 기록
  - `[WARNING]` (run_sentiment_cli): `--limit` 인자로 0이나 음수 등 비정상적인 값이 주어져 기본값(10)으로 강제 덮어씌워진 경우 기록
  - `[ERROR]`:
    - 1. 시스템 내 AI API Key가 존재하지 않아 감성 분석이 즉시 거부된 상황
    - 2. 개별 기사 분석 중 외부 AI 통신 에러 또는 결과값 파싱 에러 (추적을 위해 해당 기사의 고유 `news_id` 동시 기록)

## 7. `lib/dev/report.py`

- **모듈 역할**: 데이터 품질 지표 조회, 통계 산출 및 Matplotlib 기반의 시각화 차트(PNG)와 보고서(TXT, MD) 생성
- **로그 적용 내역**:
  - `[INFO]`: 보고서(TXT/MD) 및 시각화 차트(PNG)가 성공적으로 렌더링되어 파일 시스템에 저장된 경로를 기록 (산출물 이력 추적용)
  - `[WARNING]` (run_report_cli): CLI 명령어 입력 시 `--format`에 지원하지 않는 형식(예: pdf)을 입력하여 실행이 취소된 상황 기록
  - `[ERROR]` (\_generate_and_report 등): 디스크 용량/권한 문제나 Matplotlib 환경/한글 폰트 렌더링 충돌 등으로 인해 차트나 보고서 파일 생성이 최종 실패한 치명적 상황 기록

## 8. `lib/dev/export.py`

- **모듈 역할**: DB에 적재된 정제 뉴스를 외부 시스템 연동이나 분석을 위해 CSV, JSONL, Excel 포맷으로 변환하여 디스크에 저장
- **로그 적용 내역**:
  - `[INFO]` (run_export): 성공적으로 파일이 생성되었을 때 추출된 데이터의 건수, 포맷, 그리고 실제 저장된 파일 시스템 경로를 기록. 조건에 맞는 데이터가 없어 스킵된 일반적인 경우도 기록
  - `[WARNING]` (run_export_cli): 자동화 스크립트(CLI)에서 필수값인 `--format`을 누락하거나, 지원하지 않는 옵션을 함께 입력하여 명령이 거부된 상황
  - `[ERROR]` (run_export): 권한/디스크 용량 부족, 혹은 대용량 데이터 추출 과정에서 Pandas/Openpyxl 등 라이브러리 내부에서 예외(Exception)가 발생하여 생성에 실패한 치명적 상황

## 9. `lib/dev/list_news.py`

- **모듈 역할**: DB에 적재된 뉴스 목록을 터미널에 게시판 형태로 출력하고 페이징, 키워드 검색 등 필터링 조회 기능 제공
- **로그 적용 내역**:
  - `[INFO]` (run_board): 사용자가 어떤 필터링 옵션(키워드, 날짜, 카테고리 등)을 조합하여 게시판을 열었는지 초기 진입 상황을 기록 (사용자 검색 패턴 분석용)
  - `[WARNING]` (run_list_cli): CLI 명령어 사용 시 존재하지 않는 옵션을 입력했거나, 페이지 번호나 표시 건수에 음수/0이 입력되어 강제로 1로 보정된 상황 기록
  - `[ERROR]` (run_list_cli): CLI 파라미터 파싱 중 예상치 못한 라이브러리 레벨의 치명적 예외가 발생한 상황

## 10. `lib/dev/show.py`

- **모듈 역할**: 지정된 특정 번호(Idx)의 뉴스 기사 원문과 AI 요약, 감성 분석 결과를 통합하여 화면에 출력
- **로그 적용 내역**:
  - `[INFO]` (run_show): 기사가 정상적으로 검색되어 화면에 렌더링된 열람 기록 (기사 번호 추적)
  - `[WARNING]` (run_show, run_show_cli): 데이터베이스에 존재하지 않는 기사 번호를 요청했거나, CLI 파라미터(`--no`) 형식을 잘못 입력하여 명령이 거부된 상황
  - `[ERROR]` (run_show_cli): CLI 명령어 파싱 도중 발생한 라이브러리 차원의 치명적 구문 예외

## 11. `lib/dev/setup.py` (시스템 설정 모듈)

- **모듈 역할**: 시스템 전반의 환경설정(AI 키, 뉴스 소스, DB/로그 경로)을 TUI로 제어하고 `config.json` 및 `.env` 파일에 기록
- **로그 적용 내역**:
  - `[INFO]`: AI 설정 변경, 신규 뉴스 소스 추가, 수정, 삭제, DB 경로 변경, 로그 설정 변경 등 중요 시스템 상태가 변경될 때마다 "Audit Log(감사 로그)" 목적으로 변경 이력을 기록. 보안상 중요한 API Key 원문 등은 로그에서 제외됨

## 12. `lib/system/logger_mgr.py` (시스템 핵심)

- **모듈 역할**: 시스템 전역에서 사용할 공통 로거(Logger) 인스턴스를 초기화하고 파일 출력 설정
- **용량 관리 정책 (Log Rotation)**:
  - 시스템 리소스 최적화 및 디스크 용량 고갈 방지를 위해 `RotatingFileHandler` 적용
  - 파일 1개당 최대 용량은 `5MB`로 제한
  - 오래된 로그는 최대 `3개`까지만 백업 보관 (app.log.1, app.log.2, app.log.3)
  - 이 설정을 통해 시스템의 로그 파일은 아무리 오래 실행되어도 **최대 20MB (5MB \* 4개)를 절대 넘지 않도록 안전하게 통제**됨
