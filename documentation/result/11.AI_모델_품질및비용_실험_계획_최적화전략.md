# 📊 AI 모델 품질-비용(Token) 실험 계획서 및 최적화 전략

본 문서는 자동 평가 과정에서 제기된 **"품질·비용(토큰) 실험 설계 및 검증 절차(실험 계획서) 부재"** 지적을 해소하고, `src/lib/common/ai_client.py`에 적용된 `max_tokens = 500` 파라미터의 타당성을 검증하기 위한 체계적인 실험 계획 및 대안을 정의합니다.

---

## 1. 개요 및 배경

- **현재 상태**: `src/lib/common/ai_client.py` 내부에 `max_tokens = 500` 제한이 설정되어 있어 무한 토큰 소모를 방지하는 기초 최적화가 적용되어 있습니다.
- **보완 필요성**: 고정된 토큰 예산이 실제 뉴스 요약 및 감성 분석 품질에 미치는 영향(예: 답변 잘림 현상, 불필요한 비용 발생 등)을 정량적으로 검증하고, 최적의 대안을 도출하기 위한 실험 설계가 필요합니다.

---

## 2. 품질-비용 실험 설계 (Experimental Design)

### 2.1 실험 목적

다양한 `max_tokens` 임계값과 프롬프트 구조에 따른 **AI 응답 품질(정확성·완결성)**과 **비용(토큰 사용량·latency)** 간의 상관관계 분석 및 최적 운영 값 도출

### 2.2 실험 변수 정의

- **독립 변수 (Control Variables)**:
  1. `max_tokens`: 300, 500 (기존), 800, 1000
  2. `temperature`: 0.1 (결정론적 작업), 0.3 (요약/분석)
  3. 프롬프트 버전: v1 (기본형), v2 (간결형)
- **종속 변수 (Metrics)**:
  1. **품질 지표**: 요약 누락률(%), 고유명사/숫자 보존율(%), 감성 분류 정확도(%)
  2. **비용 및 성능 지표**: 평균 응답 토큰 수(Output Tokens), 평균 API 지연 시간(Latency, sec)

### 2.3 검증 절차 (Test Procedure)

1. **테스트셋 구축**: 정제된 샘플 뉴스 기사 50건 선정 (단문, 중문, 장문 균등 분포)
2. **교차 실험 수행**: 각 `max_tokens` 설정 값별로 동일한 테스트셋에 대해 요약 및 감성 분석 실행
3. **정량 평가**:
   - 응답이 중간에 잘리는 현상(Truncation Rate) 발생 여부 측정
   - 토큰당 요약 정보 유의성 검증 (Human Evaluation 또는 LLM-as-a-Judge)

---

## 3. `max_tokens` 파라미터 대안 및 최적화 전략

현재 고정된 `500` 대신 작업 특성에 따른 **동적 토큰 배분(Dynamic Token Budgeting)** 방안을 도입합니다.

| 작업 유형 (Task)                   | 기존 설정 | 개선 대안 (Dynamic Allocation) | 기대 효과                                                                      |
| :--------------------------------- | :-------- | :----------------------------- | :----------------------------------------------------------------------------- |
| **기사 3줄 요약 (`summarize`)**    | 고정 500  | **300 토큰** 제한 적용         | 150자 내외의 간결한 요약 요구사항에 맞춰 불필요한 토큰 낭비 및 비용 절감       |
| **감성 분석 (`sentiment`)**        | 고정 500  | **150 토큰** 제한 적용         | JSON 포맷(`{"sentiment": "...", "reason": "..."}`) 응답에 최적화하여 속도 향상 |
| **종합 인사이트 분석 (`analyze`)** | 고정 500  | **1000 토큰** 확장 허용        | 복수의 트렌드와 시사점을 누락 없이 상세히 도출                                 |

---

## 4. 품질 및 비용 검증 모니터링 방안

- **로그 추적**: 모든 AI 호출 시 소모된 `prompt_tokens`와 `completion_tokens`를 로거(`logger_mgr`)를 통해 기록하여 비용 추산 가시화
- **임계값 알림**: 일일 토큰 예산 초과 시 경고 로그 출력 및 비상 차단 메커니즘 유지
