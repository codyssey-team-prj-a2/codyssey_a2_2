# 소프트웨어 요구사항 정의서 (SRS)

- **프로젝트명**: Python CLI 기반 AI 뉴스 데이터 파이프라인 & 인사이트 리포트 자동화 서비스
- **대상 레포지토리**: `codyssey-team-prj-a2/codyssey_a2_2` (`main` 브랜치)
- **문서 버전**: v1.3.0
- **작성일**: 2026-08-14

---

## 1. 개요 (Overview)

### 1.1 목적

본 프로젝트는 외부 뉴스 소스(RSS 피드, 웹 크롤링)로부터 데이터를 자동 수집, 정제, LLM 기반 요약 및 인사이트 분석, 시각화 차트 및 리포트 생성, 데이터 내보내기까지의 전체 데이터 파이프라인을 구축하는 서비스이다.

실제 기업의 소프트웨어 개발 환경을 모의하여 **Agile 방법론 기반의 팀 협업**, **명확한 R&R(역할과 책임)**, **개인-Staging-Main으로 이어지는 배포 및 테스트 파이프라인**을 적용하여 개발 완성도와 품질을 극대화하는 것을 목적으로 한다.

### 1.2 시스템 및 개발 범위

- **프로그램 인터페이스**: 단일 진입점인 `main.py` 내에서 **대화형 콘솔 메뉴**와 **CLI 서브커맨드 실행**을 동시에 지원하여 사용 편의성 및 기능성 극대화
- **실행 환경**: Docker 컨테이너 기반의 일관된 실행 환경 제공 (`docker/Dockerfile`, `docker/docker-compose.yml`)
- **데이터 파이프라인**: 뉴스 수집(RSS/크롤링) $\rightarrow$ Raw 저장(JSONL) $\rightarrow$ 정제 및 Clean 저장(SQLite) $\rightarrow$ AI 요약/인사이트/감성 분석 $\rightarrow$ 시각화/리포트/Export
- **개발 프로세스 범위**: 칸반/간트차트 기반 Agile 협업, 역할별 분담 개발, Staging 단위 테스트 및 Main 통합 테스트 체계 수립

## 2. 팀 운영 방식 및 R&R (Methodology & Roles)

### 2.1 Agile 협업 방법론

- **업무 배분 및 추적**: 칸반(Kanban) 보드와 간트(Gantt) 차트를 활용하여 일정 및 업무 현황을 공유하고 관리한다.
- **협업 방식**: 특정 1인 주도의 개발이 아닌, 전체 팀원이 파이프라인 기능을 분담하여 수평적 책임하에 공동으로 완성한다.

### 2.2 R&R (Roles & Responsibilities)

- **PM (Project Manager)**: 프로젝트 일정/운영 관리, 스켈레톤 코드 작성, 전체 시스템 아키텍처 및 코드 구조 설계
- **개발자 1, 2 (Developers)**: 데이터 수집, 정제, AI 연동, 시각화, 리포팅 등 모듈별 기능 분담 개발
- **QA (Quality Assurance)**: 단위 테스트 및 통합 테스트 주도, 테스트 시트 작성, 예외 상황 검증 및 버그 리포팅

### 2.3 개발 및 배포 환경 파이프라인

- **개인 Repository**: 각 팀원의 개인 레포지토리에서 기능 단위 개발 및 커밋
- **Staging Environment (`staging` repo/branch)**: 1차 병합 후 QA 주도의 **단위 테스트(Unit Test)** 및 개별 기능 검증 수행 (Docker 환경 기반)
- **Main Environment (`main` repo/branch)**: 최종 통합 및 QA 주도의 **통합 테스트(Integration Test)** 검증 후 최종 제출

## 4. 기능 요구사항 (Functional Requirements)

### 4.1 프로그램 인터페이스 (Dual Interface in `main.py`)

- **[FR-00-01] 대화형 메뉴**: 인자 없이 `main.py` 실행 시 대화형 콘솔 메뉴로 진입하여, 비전문가도 번호 선택만으로 전체 데이터 파이프라인을 쉽게 제어할 수 있도록 한다.
- **[FR-00-02] CLI 서브커맨드 지원**: `main.py` 실행 시 CLI 인자(`fetch`, `clean`, `summarize`, `analyze`, `report`, `export`, `list`, `show`)를 직접 전달하여 대화형 화면 없이 서브커맨드를 즉시 수행할 수 있도록 한다.

### 4.2 뉴스 수집 (`fetch`)

- **[FR-01-01] 수집 수단**: 공개 뉴스 RSS 피드 파싱, REST API 연동(JSON), 웹 크롤링(BeautifulSoup/Selenium) 세 가지 방식을 지원한다.
- **[FR-01-02] 오류 및 타임아웃 방어**: HTTP 통신 시 타임아웃을 설정하며, 연결 실패, 404 에러, URL 누락 발생 시 예외 로깅 후 개별 항목을 스킵한다.
- **[FR-01-03] Raw 저장 및 1차 정제**: 수집 단계에서 웹 노이즈(스크립트, 스타일 태그 등)를 1차 제거한 순수 텍스트 본문과 메타데이터(collected_at, source_name, method 등)를 JSONL 파일로 저장한다.
- **[FR-01-04] 수집 건수 인자 검증**: CLI 실행 시 --limit 인자에 0, 음수, 비숫자 문자열 입력 시 경고 메시지를 출력하고 기본값(20건)으로 폴백 처리한다.
- **[FR-01-05] 로봇 배제 표준 준수**: 외부 웹사이트 크롤링 및 본문 심층 수집 전, 대상 도메인의 robots.txt 정책을 사전에 검증(can_fetch)하여 허용된 영역만 수집한다.
- **[FR-01-06] 투명한 봇 식별**: 모든 네트워크 요청 및 브라우저 구동 시 프로젝트 식별자와 목적이 명시된 전용 User-Agent 헤더(`CodysseyNewsBot/1.0`)를 사용한다.

### 4.3 데이터 정제 (`clean`)

- **[FR-02-01] 데이터 품질 검증 및 2차 안전망**: Raw 데이터 내 결측치(제목/URL) 검증을 수행하며, 예기치 않은 HTML 태그 잔여물이 있을 경우 2차로 정제(Strip)한다.
- **[FR-02-02] 날짜 규격 통일**: 다양한 날짜 포맷(RFC822, ISO8601 등)을 `YYYY-MM-DD` 표준 포맷으로 통일 파싱한다.
- **[FR-02-03] 중복 처리 정책 분기**:
  - `skip`: 기존 Clean DB에 존재하는 기사는 저장 스킵
  - `upsert`: 기존 기사 정보를 최신 정제 데이터로 갱신
- **[FR-02-04] Clean DB 저장**: 정제 완료 데이터는 SQLite DB(`codyssey.db`)의 `clean_news` 테이블에 저장하며, created_at 컬럼은 대한민국 표준시(KST) 기준 로컬 타임스탬프를 기록한다. 그리고 `storage.db_path` 설정 경로를 동적 참조한다.

### 4.4 AI 요약 및 인사이트 분석 (`summarize`, `analyze`)

- **[FR-03-01] Multi-LLM 연동**: Gemini, OpenAI, Anthropic SDK 연동 분기 구조를 지원한다 (`ai_client.py`).
- **[FR-03-02] 요약 옵션 및 한계값 검증**: `--all`, `--id`, `--unsummarized` 플래그를 지원한다. `--limit`에 음수 입력 시 기본값(10건)으로 폴백하며, 이미 요약된 기사는 기본 스킵 처리한다.
- **[FR-03-03] LLM 답변 제어**: Gemini 2.5 Flash 모델 연동 시 답변 끊김 방지를 위해 `thinking_budget=0`을 지정하여 3문장 이내 요약문을 생성하고 `ai_summary` 테이블에 저장한다.
- **[FR-03-04] AI 인사이트 도출**: 지정 기간 및 카테고리 뉴스를 수합하여 주요 트렌드, 핵심 키워드, 시사점을 추출하고 `ai_insight` 테이블에 저장한다.
- **[FR-03-05] 날짜 포맷 입력 검증**: 조회 및 분석 시 `--date-from`, `--date-to` 입력값에 대해 `YYYY-MM-DD` 형식 검증을 수행하여, 잘못된 포맷 입력 시 오류 안내 후 처리를 중단한다.

### 4.5 시각화, 리포트 및 내보내기 (`report`, `export`)

- **[FR-04-01] 차트 시각화**: Matplotlib 기반으로 카테고리별 뉴스 수, 일자별 수집 추이, 감성 분포 차트를 생성하여 PNG 파일로 저장한다.
- **[FR-04-02] 품질 지표 및 집계**: 정제 통과율, 요약 성공률 지표와 카테고리/키워드 Top N 집계 쿼리를 수행한다.
- **[FR-04-03] 리포트 생성**: 콘솔 화면 출력 및 파일(TXT, MD) 저장 기능을 제공한다.
- **[FR-04-04] 데이터 내보내기**: CSV, JSONL, Excel 파일 내보내기를 지원하며, 요약 완료 기사 필터링(`--status summarized`)을 제공한다.

### 4.6 보너스 기능 요구사항

- **[FR-05-01] CLI 데이터 탐색 (`list`, `show`)**: 뉴스 목록 조회 및 상세 조회를 제공하며, 페이지네이션(`--page`, `--size`) 및 카테고리 필터를 지원한다. (페이지/사이즈 음수 입력 시 1로 보정)
- **[FR-05-02] 감성 분석 (`sentiment`)**: 뉴스의 감성(긍정/부정/중립)을 AI로 분석하고 `sentiment_analysis` 테이블 저장 및 차트에 반영한다.
- **[FR-05-03] 정기 실행 스케줄링 가이드**: `main.py` CLI 서브커맨드 명령어를 활용하여 Mac/Linux(`cron`) 에 등록하는 가이드를 제공한다.

## 5. 비기능 요구사항 (Non-Functional Requirements)

- **[NFR-01] 보안성**: API Key 및 DB 파일 경로는 소스코드에 하드코딩하지 않으며 `config.json` 및 환경변수에서 읽어온다.
- **[NFR-02] 예외 처리 및 안정성**: 외부 API 통신 장애, 파라미터 오입력, 잘못된 날짜 포맷 입력 시 프로그램이 비정상 종료되지 않고 경고 메시지 출력 후 안전하게 제어권을 유지한다.
- **[NFR-03] 로깅(Logging)**: Python `logging` 모듈을 이용하여 주요 처리 단계별 `INFO`, `WARNING`, `ERROR` 레벨 로그를 콘솔 및 파일에 기록한다.
- **[NFR-04] 수집 윤리**: 크롤링 요청 간 지연(Delay)을 두어 대상 웹사이트에 과도한 트래픽 부하를 주지 않도록 구현한다.
- **[NFR-05] 품질 보증(QA)**: Staging 단계에서 단위 테스트를 수행하고, Main 단계에서 통합 테스트를 수행하며, 검증 결과는 QA가 작성하는 테스트 시트로 문서화한다.
