#### 본 문서는 스케줄링 아키텍팅과 기본적인 설정방법을 설명하기 위해 작성된 문서임. 실제는 run.sh 실행으로 스케줄링까지 자동으로 수행하도록 처리해둠.

---

## 1. 개요 (Overview)

본 프로젝트는 호스트 OS(Mac, Windows 등)의 로컬 스케줄러를 직접 설정하는 번거로움을 없애고, **Docker 컨테이너 내부에 내장된 Linux `cron` 데몬과 실행 래퍼 스크립트(`script/scheduled_fetch.sh`)를 활용**합니다[cite: 1, 2]. 이를 통해 운영체제 환경에 구애받지 않고 100% 동일한 환경에서 정기 뉴스 수집(fetch) 파이프라인이 자동 실행됩니다[cite: 1, 2].

### 1.1 스케줄링 아키텍처 및 핵심 파일 역할

1. **`script/scheduled_fetch.sh` (실행 래퍼 스크립트)**[cite: 1]
   - 컨테이너 내부의 cron이 주기적으로 호출하는 진입점입니다[cite: 1, 2].
   - 컨테이너 내부 경로로 진입하여 비대화형 CLI 라우터인 `automation.py`를 실행합니다[cite: 1].
2. **Docker Native Cron 동작 흐름**[cite: 2]
   - `Dockerfile` 빌드 시 `cron` 패키지가 설치되며, 설정된 주기(`*/10 * * * *`)로 `script/scheduled_fetch.sh`를 실행하도록 등록됩니다[cite: 2].
   - 컨테이너가 `docker compose up -d`로 실행될 때 `ENTRYPOINT`를 통해 `cron` 백그라운드 서비스가 활성화됩니다[cite: 2].
   - 오직 뉴스 수집만 백그라운드에서 주기적으로 수행되며, 모든 실행 결과 및 에러 로그는 `logs/cron_fetch.log`에 자동 기록됩니다[cite: 1, 2].

---

## 2. 사전 준비 (Prerequisites)

1. `src/config.json`에 뉴스 소스가 최소 1개 이상 등록되어 있어야 합니다. (대화형 메뉴 '환경 설정' 선행 필수)[cite: 1, 2]
2. `script/scheduled_fetch.sh` 파일의 줄바꿈 형식이 반드시 **`LF` (리눅스 포맷)**인지 확인합니다. (Windows 사용자는 IDE 우측 하단 설정 확인 필수)[cite: 2]
3. 로컬에 구버전 이미지가 남아있다면 캐시를 비우고 새로 빌드합니다[cite: 2].
   ```bash
   cd docker
   docker compose build --no-cache
   ```

---

## 3. 스케줄러 백그라운드 실행 방법

로컬 터미널에서 `./run.sh`로 실행하면 터미널을 끄거나 세션이 종료될 때 컨테이너도 함께 종료되므로 스케줄러 용도로 적합하지 않습니다. 24시간 백그라운드에서 정기 수집이 돌게 하려면 **데몬(Detached) 모드**로 실행해야 합니다[cite: 2].

### 3.1 스케줄러 켜기 (백그라운드 실행)

```bash
cd docker
docker compose up -d
```

### 3.2 스케줄러 작동 로그 실시간 확인하기

`script/scheduled_fetch.sh`가 주기적으로 잘 돌고 있는지 확인하려면 아래 명령어로 로그를 조회합니다[cite: 1, 2].

```bash
tail -f ../logs/cron_fetch.log
```

### 3.3 스케줄러 끄기

정기 수집을 중단하거나 컨테이너를 내릴 때는 아래 명령어를 사용합니다[cite: 2].

```bash
cd docker
docker compose down
```

---

## 4. 스케줄 주기 변경 방법

- **주기 변경**: `docker/Dockerfile` 내부의 `*/10 * * * *` (10분 주기) 부분을 원하는 cron 표현식으로 수정한 뒤, 이미지를 다시 빌드(`docker compose build --no-cache`)하면 반영됩니다[cite: 2].
