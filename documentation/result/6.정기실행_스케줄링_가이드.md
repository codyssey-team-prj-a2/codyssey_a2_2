## 1. 개요 (Overview)

터미널 접속 없이(cron, launchd, Windows 작업 스케줄러 등) 뉴스 수집 파이프라인을 **정기적으로 자동 실행**하기 위한 실행 파일과 등록 방법을 설명한다. 실무에서 스케줄러를 다루는 환경은 macOS가 많다는 전제로, **macOS(`crontab`) 기준을 기본으로 설명**하고 Windows(작업 스케줄러) 방법을 추가로 안내한다.

### 1.1 왜 `main.py`가 아니라 `automation.py`인가

`main.py`는 인자 없이 실행하면 항상 대화형 콘솔 메뉴(TUI)로 진입하는 구조이고, 스케줄러 같은 비대화형 환경에서는 `input()` 대기 때문에 그대로 자동 실행할 수 없다. `main.py`/`setup.py`는 팀 합의로 건드리지 않기로 했으므로, 대신 신규 파일 `src/automation.py`를 비대화형 전용 진입점으로 추가했다. `main.py`의 서브메뉴에서 "CLI 직접 입력"으로 쓰는 것과 **동일한 서브커맨드/옵션 문법**을 그대로 사용하므로, `documentation/result/4.CLI_및_AI_프롬프트명세서.md`의 옵션 표를 그대로 참고하면 된다.

### 1.2 이번에 추가된 파일

| 파일 | 역할 |
| :--- | :--- |
| `src/automation.py` | 비대화형 CLI 라우터. `python3 automation.py <서브커맨드> [옵션...]` 형태로 실행 |
| `script/scheduled_fetch.sh` | macOS/Linux `cron`용 실행 래퍼 (Docker 컨테이너 안에서 `automation.py` 호출) |
| `script/scheduled_fetch.ps1` | Windows 작업 스케줄러용 실행 래퍼 (PowerShell) |

`automation.py`가 지원하는 서브커맨드는 `main.py` 대화형 메뉴가 인식하는 것과 동일하다: `fetch`, `clean`, `summarize`, `analyze`, `report`, `export`, `list`, `show`, `sentiment`. 실행 전 **환경설정(1번 메뉴)이 3/3 완료**되어 있지 않으면 안내 메시지를 출력하고 종료한다(AI API 키, 뉴스 소스 1개 이상, 로그 설정).

## 2. 사전 준비 (Prerequisites)

1. `README.md` 2.2절대로 Docker 이미지가 이미 빌드되어 있어야 한다(`cd docker && ./run.sh build`).
2. `src/config.json`에 뉴스 소스가 최소 1개 등록되어 있고, `src/.env`에 AI API 키가 채워져 있어야 한다(대화형 메뉴 1번 환경설정을 한 번은 수동으로 완료해 둔다). 이 둘이 안 되어 있으면 `automation.py`가 곧바로 오류를 내고 종료한다.
3. **Docker Desktop이 실행 중이어야 한다.** 스케줄러가 트리거되는 시점에 Docker 데몬이 꺼져 있으면 `docker compose` 명령 자체가 실패한다 — macOS는 Docker Desktop의 "Start Docker Desktop when you log in" 옵션을, Windows는 "Start Docker Desktop when you sign in"을 켜 둔다.

## 3. macOS/Linux — `crontab` 등록 (기본)

### 3.1 실행 스크립트에 실행 권한 부여

```bash
cd /path/to/news_pipeline
chmod +x script/scheduled_fetch.sh
```

### 3.2 수동으로 한 번 실행해서 검증

cron에 등록하기 전에 터미널에서 직접 실행해 정상 동작을 먼저 확인한다.

```bash
./script/scheduled_fetch.sh
```

`[명령어 실행]`으로 시작하는 로그와 함께 뉴스 수집 결과가 출력되면 정상이다.

### 3.3 crontab 등록

```bash
crontab -e
```

에디터가 열리면 아래와 같은 줄을 추가한다(매일 새벽 6시 실행 예시):

```cron
0 6 * * * cd /path/to/news_pipeline && ./script/scheduled_fetch.sh >> /path/to/news_pipeline/logs/cron_fetch.log 2>&1
```

- `crontab` 문법은 `분 시 일 월 요일 명령어` 순서다. 예시(`0 6 * * *`)는 "매일 06:00"을 의미한다.
- 스크립트 경로는 **반드시 절대경로**로 지정한다(cron은 홈 디렉토리를 기준으로 실행되고 상대경로를 해석하지 못한다).
- `>> .../cron_fetch.log 2>&1`로 표준출력/에러를 로그 파일에 append한다 — cron은 결과를 화면에 보여주지 않으므로 로그 리다이렉션이 사실상 필수다.
- `docker` 실행 파일을 cron이 못 찾으면(`docker: command not found`) `DOCKER_BIN` 환경변수로 절대경로를 지정한다. 절대경로는 `which docker`로 확인한다.

```cron
0 6 * * * DOCKER_BIN=/usr/local/bin/docker cd /path/to/news_pipeline && ./script/scheduled_fetch.sh >> /path/to/news_pipeline/logs/cron_fetch.log 2>&1
```

### 3.4 등록 확인 / 삭제

```bash
crontab -l      # 등록된 목록 확인
crontab -e      # 수정(해당 줄 삭제 후 저장하면 취소됨)
tail -f logs/cron_fetch.log   # 실행 로그 실시간 확인
```

### 3.5 참고 — macOS에서 `cron` 대신 `launchd`를 고려할 수도 있음

macOS는 절전(sleep) 상태에서 `cron` 작업이 건너뛰어질 수 있다. 노트북처럼 항상 켜져 있지 않은 환경에서 더 안정적으로 돌리고 싶다면, macOS 네이티브 스케줄러인 `launchd`(`~/Library/LaunchAgents/`에 `.plist` 등록)를 대안으로 쓸 수 있다. 이번 산출물은 요구사항(FR-05-03)에 맞춰 범용적인 `crontab` 방식을 기본으로 제공하며, `launchd`가 필요하면 `script/scheduled_fetch.sh`를 그대로 `ProgramArguments`에 지정해서 재사용할 수 있다(스크립트 자체는 동일하게 쓰면 됨).

## 4. Windows — 작업 스케줄러 등록 (추가)

### 4.1 PowerShell 실행 정책 확인

Windows는 기본적으로 로컬 `.ps1` 스크립트 실행이 제한되어 있을 수 있다. 관리자 권한 PowerShell에서 한 번 확인/설정한다.

```powershell
Get-ExecutionPolicy
# Restricted면 아래처럼 현재 사용자 범위만 완화
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### 4.2 수동 실행으로 먼저 검증

```powershell
cd D:\path\to\news_pipeline
.\script\scheduled_fetch.ps1
```

### 4.3 작업 스케줄러(schtasks) 명령줄 등록

매일 06:00 실행 예시(관리자 권한 PowerShell/CMD):

```powershell
schtasks /Create /TN "CodysseyNewsFetch" /TR "powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\path\to\news_pipeline\script\scheduled_fetch.ps1" /SC DAILY /ST 06:00
```

- `/TN`: 작업 이름, `/TR`: 실행할 명령, `/SC DAILY /ST 06:00`: 매일 06:00 트리거.
- 로그가 필요하면 `.ps1` 자체에서 `Start-Transcript`를 쓰거나, 명령 뒤에 `*> D:\...\logs\cron_fetch.log`로 리다이렉션을 추가한다.

### 4.4 GUI(작업 스케줄러 앱)로 등록하는 경우

1. `작업 스케줄러` 앱 실행 → `기본 작업 만들기`
2. 트리거: 매일 → 원하는 시각 지정
3. 동작: `프로그램 시작` → 프로그램/스크립트에 `powershell.exe` 입력
4. 인수 추가: `-NoProfile -ExecutionPolicy Bypass -File "D:\path\to\news_pipeline\script\scheduled_fetch.ps1"`
5. 마침 후, 작업 속성 → 일반 탭에서 "사용자가 로그온했는지 여부에 관계없이 실행" 체크(로그오프 상태에서도 동작하게 하려면 필요) — 단, 이 옵션은 Docker Desktop이 백그라운드 서비스로 계속 떠 있어야 정상 동작한다.

### 4.5 등록 확인 / 삭제

```powershell
schtasks /Query /TN "CodysseyNewsFetch"
schtasks /Delete /TN "CodysseyNewsFetch" /F
```

## 5. 트러블슈팅 (Troubleshooting)

| 증상 | 원인 / 조치 |
| :--- | :--- |
| `the input device is not a TTY` | `docker compose run`에 `-T` 옵션이 빠진 경우. 제공된 스크립트는 이미 `-T`를 포함하고 있으므로, 스크립트를 직접 수정했다면 옵션이 유지되는지 확인한다. |
| `docker: command not found` (cron) | cron은 로그인 셸과 다른(축소된) `PATH`를 쓴다. `which docker`로 절대경로를 확인해 `DOCKER_BIN` 환경변수로 지정한다. |
| `Cannot connect to the Docker daemon` | Docker Desktop이 꺼져 있는 경우. 로그인 시 자동 실행 옵션을 켜 두거나, 스케줄 시각 이전에 켜져 있는지 확인한다. |
| `[오류] 환경설정이 완료되지 않았습니다 (n/3)` | 컨테이너 안 `src/config.json`/`src/.env`에 AI 키·뉴스 소스·로그 설정이 비어 있는 경우. 대화형 메뉴 1번(환경 설정)을 한 번 완료해 둔다. |
| 실행은 됐는데 결과가 안 보임(cron) | cron은 표준출력을 화면에 보여주지 않는다. `>> logfile 2>&1` 리다이렉션이 붙어 있는지, 로그 파일이 실제로 갱신되는지(`tail -f`) 확인한다. |

## 6. 검증 방법 요약

1. `./script/scheduled_fetch.sh`(또는 `.ps1`)를 터미널에서 **수동 실행**해 정상 종료(exit code 0)와 수집 결과를 먼저 확인한다.
2. crontab/작업 스케줄러에 등록 후, 트리거 시각을 가까운 시간(예: 1~2분 뒤)으로 임시로 바꿔 **실제 트리거 동작**을 1회 확인한다.
3. 확인이 끝나면 원하는 운영 스케줄(예: 매일 06:00)로 시각을 되돌린다.
4. `main.py` 대화형 메뉴의 `8. 뉴스 목록 조회`로 새로 수집된 기사가 쌓였는지 최종 확인한다.
