## Cli 정의

# 💻 뉴스 데이터 파이프라인 CLI 설계 명세서

**명령어 기본 구조:** `[서브커맨드] [옵션]`

| 서브커맨드               | 기능 설명                                     | 옵션 파라미터 (단축키)  | 구분     | 옵션 상세 설명                              | 설계 리뷰 포인트 (개발 시 주의사항)                                                                |
| ------------------------ | --------------------------------------------- | ----------------------- | -------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **`fetch`**              | 외부 뉴스를 수집하여<br>`raw` 저장소에 적재   | `--source` (`-s`)       | **필수** | 수집 대상 소스 (예: `naver`, `daum`)        | • RSS/API 장애 대비 예외 처리(Try-Except) 필수<br>• 타임아웃 발생 시 로깅 남기고 뻗지 않게 처리    |
|                          |                                               | `--limit` (`-l`)        | 선택     | 최대 수집 건수 (기본: `50`)                 |                                                                                                    |
| **`clean`**              | `raw`를 정제하여<br>`clean` 저장소에 저장     | `--strategy`            | 선택     | `skip`, `upsert` (기본: `config.json` 참조) | • 날짜 형식 통일(`YYYY-MM-DD`) 철저히 할 것<br>• DB 저장 시 `news_id` 기준 충돌(Conflict) 처리     |
| **`summarize`**          | `clean` 뉴스를AI 요약 후 업데이트             | `--unsummarized` (`-u`) | 선택     | 요약 안 된 기사(`is_summarized=0`)만 대상   | • **API 토큰 낭비 방지:** 이미 요약된 기사는 기본 스킵 처리                                        |
|                          |                                               | `--all` (`-a`)          | 선택     | 전체 뉴스 요약 진행 (플래그)                |                                                                                                    |
|                          |                                               | `--id` (`-i`)           | 선택     | 특정 뉴스 ID 1건만 요약                     |                                                                                                    |
|                          |                                               | `--limit` (`-l`)        | 선택     | 한 번에 요약할 최대 건수 제한               | —id 에서는 limit 이 동작하지 않는다는 안내 문구 출력                                               |
| **`analyze`**            | 카테고리/기간별 묶어<br>종합 AI 인사이트 도출 | `--date-from`           | 필수1    | 분석 대상 시작일 (예: `2026-08-01`)         | • **메모리 보호 & 시의성:** 기간 미지정 시 기본값을 '최근 7일'로 제한하여 전체 DB 조회를 방지할 것 |
|                          |                                               | `--date-to`             | 필수1    | 분석 대상 종료일 (예: `2026-08-07`)         |                                                                                                    |
|                          |                                               | `--category` (`-c`)     | 필수2    | 특정 카테고리만 대상 (예: `IT`)             |                                                                                                    |
| **`report`**             | 지표, 차트 생성 및<br>종합 리포트 출력        | `--date-from` / `to`    | 선택     | 리포트 집계 대상 날짜 범위                  | • 품질 지표 및 TOP N 집계 SQL 쿼리에 기간(`BETWEEN`) 필수 반영                                     |
|                          |                                               | `--format` (`-f`)       | 선택     | `console`, `txt`, `md` (기본: `console`)    |                                                                                                    |
| **`export`**             | `clean` 데이터를<br>파일 포맷으로 내보내기    | `--format` (`-f`)       | **필수** | 내보낼 포맷 (`csv`, `jsonl`, `excel`)       | • 파이썬 `csv` 또는 `pandas` 모듈 활용 권장                                                        |
|                          |                                               | `--status`              | 선택     | 요약 상태 필터링 (`summarized`, `all`)      |                                                                                                    |
|                          |                                               | `--date-from` / `to`    | 선택     | 내보낼 데이터의 날짜 범위 제한              |                                                                                                    |
| **`list`**<br>_(보너스)_ | 정제된 뉴스의<br>목록 조회 및 페이징          | `--page` (`-p`)         | 선택     | 조회 페이지 번호 (기본: `1`)                | • SQLite `LIMIT`과 `OFFSET` 구문을 사용하여 페이징 로직 구현                                       |
|                          |                                               | `--size`                | 선택     | 페이지당 표시 건수 (기본: `10`)             |                                                                                                    |
|                          |                                               | `--category` (`-c`)     | 선택     | 카테고리 필터링                             |                                                                                                    |
| **`show`**<br>_(보너스)_ | 특정 뉴스의 상세<br>정보(본문, 요약) 조회     | `--id` (`-i`)           | **필수** | 조회할 기사의 고유 ID                       | • 화면 출력 시 줄바꿈 등 가독성 고려 렌더링                                                        |
