# 정기 실행 스케줄링 가이드 (Scheduling Guide)

- **프로젝트명**: Python CLI 기반 AI 뉴스 데이터 파이프라인 & 인사이트 리포트 자동화 서비스
- **대상 레포지토리**: `codyssey-team-prj-a2/codyssey_a2_2` (`main` 브랜치)
- **문서 버전**: v2.0.0 (Docker Native Cron 아키텍처 도입)
- **작성일**: 2026-08-14

---

## 1. 개요 (Overview)

본 프로젝트는 호스트 OS(Mac, Windows 등)의 로컬 스케줄러(crontab, 작업 스케줄러)를 사용하지 않습니다. 대신 **Docker 컨테이너 내부에 내장된 Linux `cron` 데몬을 활용**하여 운영체제에 구애받지 않고 100% 동일한 환경에서 10분 단위 정기 뉴스 수집(fetch) 파이프라인을 자동 실행합니다.

### 1.1 스케줄링 아키텍처

1. `Dockerfile` 빌드 시 `cron` 패키지가 설치되며, 10분(`*/10 * * * *`) 주기로 스케줄이 자동 등록됩니다.
2. 컨테이너가 실행될 때 `ENTRYPOINT`를 통해 `cron` 백그라운드 서비스가 켜집니다.
3. 10분마다 호스트와 마운트된 `script/scheduled_fetch.sh`를 실행하여 뉴스를 수집합니다.
4. AI 요약이나 감성 분석 등 리소스가 많이 소모되는 작업은 제외하고, 오직 뉴스 수집만 백그라운드에서 진행합니다.
5. 모든 실행 기록은 `logs/cron_fetch.log`에 자동 저장됩니다.

---

## 2. 사전 준비 (Prerequisites)

1. `src/config.json`에 뉴스 소스가 최소 1개 등록되어 있어야 합니다. (대화형 메뉴 '환경 설정' 선행 필수)
2. `script/scheduled_fetch.sh` 파일의 줄바꿈 형식이 반드시 **`LF` (리눅스 포맷)**인지 확인합니다. (Windows 사용자는 IDE 우측 하단 확인 필수)
3. 로컬에 기존 이미지가 남아있다면 캐시를 지우고 새로 빌드해야 합니다.
   ```bash
   cd docker
   docker compose build --no-cache
   ```

## 3. 스케줄러 백그라운드 실행 방법

기존에 사용하던 `./run.sh`는 터미널을 끄면 컨테이너도 같이 죽기 때문에 스케줄러 용도로 적합하지 않습니다. 스케줄러가 24시간 백그라운드에서 계속 돌게 하려면 **데몬(Detached) 모드**로 실행해야 합니다.

### 3.1 스케줄러 켜기

```bash
cd docker
docker compose up -d
```

위 명령어를 치면 컨테이너가 백그라운드로 전환되며, 창을 닫아도 10분마다 뉴스를 알아서 수집합니다.

### 3.2 스케줄러 작동 로그 확인하기

스케줄러가 잘 돌고 있는지 실시간으로 보려면 아래 명령어를 사용합니다.

```bash
tail -f ../logs/cron_fetch.log
```

### 3.3 스케줄러 끄기

더 이상 정기 수집을 원하지 않거나 프로그램을 종료할 때는 아래 명령어로 컨테이너를 내립니다.

```bash
cd docker
docker compose down
```

## 4. 스케줄 주기 변경 방법

- **주기 변경**: `docker/Dockerfile` 내부의 `*/10 * * * *` 부분을 원하는 cron 표현식으로 수정한 뒤 이미지를 다시 빌드합니다. (예: `0 * * * *` = 1시간마다)
