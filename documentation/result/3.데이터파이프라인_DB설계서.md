## 1. 개요 및 하이브리드 저장소 전략 (Overview & Hybrid Strategy)

본 시스템은 데이터 생애주기(Data Lifecycle) 및 처리 단계별 요구사항에 최적화된 **하이브리드 저장소 아키텍처(Hybrid Storage Architecture)**를 채택한다[cite: 1].

```text
[ 수집 단계 (Raw) ]                    [ 정제/분석/출력 단계 (Clean) ]
┌────────────────────────┐            ┌────────────────────────┐
│  JSONL (Files)         │  ──Clean─► │  SQLite (codyssey.db)  │
│  - Schemaless, Append  │   (clean)  │  - RDBMS, Upsert, Index│
│  - 원본 무결성 보존        │            │  - 빠른 검색 및 TOP N     │
└────────────────────────┘            └────────────────────────┘
```

### 1.1 하이브리드 채택 사유 (Why Hybrid?)

1. **Raw 데이터 계층 (JSONL)**:[cite: 1]
   - **유연성**: 언론사/RSS/웹페이지마다 달라지는 규격을 사전 스키마 정의 없이 수용[cite: 1].
   - **무결성 및 백업**: 파일 끝에 이어 붙이는 Append-only 방식으로 기록 속도가 빠르며 원본 데이터 훼손 방지[cite: 1].
2. **Clean 및 Insight 계층 (SQLite)**:[cite: 1]
   - **트랜잭션 및 Upsert**: `ON CONFLICT` 구문을 활용하여 중복 방지 및 최신화 처리[cite: 1].
   - **인덱스 및 집계 속도**: 카테고리/기간별 빠른 검색과 `GROUP BY` 기반의 TOP N 집계 연산 최적화[cite: 1].

## 2. Raw 데이터 저장소 규격 (JSONL)

- **저장 위치**: `./data/raw/{source_name}.jsonl` (설정된 `raw_path` 참조)[cite: 1]
- **저장 방식**: Line-delimited JSON (Append Mode)[cite: 1]

### 2.1 JSONL 레코드 스키마

```json
{
	"source_name": "google_news_it_rss",
	"method": "rss",
	"category": "IT",
	"title": "기사 제목 텍스트",
	"content": "기사 본문 또는 요약 텍스트",
	"url": "https://example.com/news/123",
	"published_at": "Mon, 12 Aug 2026 05:00:00 GMT",
	"collected_at": "2026-08-14T01:30:00.000000+00:00"
}
```

## 3. Clean 데이터베이스 스키마 설계 (SQLite)

- **DB 파일 위치**: `storage.db_path` 설정 경로 (`./data/codyssey.db`)[cite: 1]
- **초기화 스크립트**: `src/lib/db/schema.sql` 및 `sqlite_mgr._migrate_schema()`[cite: 1]

### 3.1 테이블 1: `clean_news` (정제된 뉴스 및 AI 분석 데이터)

수집 및 정제 과정을 거친 표준화된 뉴스 데이터를 보관하며, AI 요약 및 감성 분석 결과를 함께 관리한다[cite: 1].

| 컬럼명                 | 자료형    | 제약조건                    | 설명 (용도)                                             |
| :--------------------- | :-------- | :-------------------------- | :------------------------------------------------------ |
| **`news_id`**          | `TEXT`    | **PRIMARY KEY**             | 기사 고유 식별자 (URL). 중복 처리(Upsert) 기준[cite: 1] |
| **`source`**           | `TEXT`    | `NOT NULL`                  | 언론사 또는 피드 출처 (예: google_news_it_rss)[cite: 1] |
| **`category`**         | `TEXT`    | `NOT NULL`                  | 카테고리 (예: IT, Tech, 종합). 검색 필터용[cite: 1]     |
| **`title`**            | `TEXT`    | `NOT NULL`                  | 기사 제목[cite: 1]                                      |
| **`content`**          | `TEXT`    | `NOT NULL`                  | 정제(HTML 태그 제거 등) 완료된 기사 본문[cite: 1]       |
| **`pub_date`**         | `TEXT`    | `NOT NULL`                  | 통일된 발행일 포맷 (`YYYY-MM-DD`). 기간 검색용[cite: 1] |
| **`ai_summary`**       | `TEXT`    | `NULL`                      | AI가 생성한 3줄 요약문 (초기값 NULL)[cite: 1]           |
| **`is_summarized`**    | `INTEGER` | `DEFAULT 0`                 | 요약 완료 여부 (`0`: 미완료, `1`: 완료)[cite: 1]        |
| **`sentiment`**        | `TEXT`    | `NULL`                      | AI 감성 분석 결과 (`긍정`, `부정`, `중립`)[cite: 1]     |
| **`sentiment_reason`** | `TEXT`    | `NULL`                      | AI 감성 분석 판단 사유[cite: 1]                         |
| **`created_at`**       | `TEXT`    | `DEFAULT CURRENT_TIMESTAMP` | DB 레코드 생성 시각[cite: 1]                            |

#### SQL DDL (`clean_news`)

```sql
CREATE TABLE IF NOT EXISTS clean_news (
    news_id TEXT PRIMARY KEY,
    source TEXT NOT NULL,
    category TEXT NOT NULL,
    title TEXT NOT NULL,
    content TEXT NOT NULL,
    pub_date TEXT NOT NULL,
    ai_summary TEXT,
    is_summarized INTEGER DEFAULT 0,
    sentiment TEXT,
    sentiment_reason TEXT,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_clean_news_category ON clean_news(category);
CREATE INDEX IF NOT EXISTS idx_clean_news_pub_date ON clean_news(pub_date);
CREATE INDEX IF NOT EXISTS idx_clean_news_is_summarized ON clean_news(is_summarized);
```

### 3.2 테이블 2: `ai_insight` (종합 인사이트 분석 결과)

기간 및 카테고리별로 AI가 종합 추출한 트렌드, 핵심 키워드, 시사점 분석 결과를 보관한다[cite: 1].

| 컬럼명                | 자료형    | 제약조건                      | 설명 (용도)                                  |
| :-------------------- | :-------- | :---------------------------- | :------------------------------------------- |
| **`insight_id`**      | `INTEGER` | **PRIMARY KEY AUTOINCREMENT** | 분석 결과 고유 번호[cite: 1]                 |
| **`target_category`** | `TEXT`    | `NOT NULL`                    | 분석 대상 카테고리 (예: IT, ALL)[cite: 1]    |
| **`period_from`**     | `TEXT`    | `NOT NULL`                    | 분석 대상 시작일 (`YYYY-MM-DD`)[cite: 1]     |
| **`period_to`**       | `TEXT`    | `NOT NULL`                    | 분석 대상 종료일 (`YYYY-MM-DD`)[cite: 1]     |
| **`main_trend`**      | `TEXT`    | `NOT NULL`                    | AI 추출 주요 트렌드[cite: 1]                 |
| **`core_keywords`**   | `TEXT`    | `NOT NULL`                    | 콤마(`,`)로 구분된 핵심 키워드 목록[cite: 1] |
| **`implications`**    | `TEXT`    | `NOT NULL`                    | 비즈니스 시사점 및 시사 분석[cite: 1]        |
| **`created_at`**      | `TEXT`    | `DEFAULT CURRENT_TIMESTAMP`   | 분석 수행 시각[cite: 1]                      |

#### SQL DDL (`ai_insight`)

```sql
CREATE TABLE IF NOT EXISTS ai_insight (
    insight_id INTEGER PRIMARY KEY AUTOINCREMENT,
    target_category TEXT NOT NULL,
    period_from TEXT NOT NULL,
    period_to TEXT NOT NULL,
    main_trend TEXT NOT NULL,
    core_keywords TEXT NOT NULL,
    implications TEXT NOT NULL,
    created_at TEXT DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(target_category, period_from, period_to)
);

CREATE INDEX IF NOT EXISTS idx_ai_insight_period ON ai_insight(target_category, period_from, period_to);
```

## 4. 데이터파이프라인 흐름 및 변환 규격 (Pipeline Transformations)

```text
[Fetch] ──► [Raw JSONL] ──► [Clean] ──► [SQLite DB] ──► [AI / Report / Export]
```

### 4.1 파이프라인 단계별 변화 명세

1. **수집 (`fetch.py` $\rightarrow$ `raw_store.py`)**:[cite: 1]
   - 외부 RSS XML / HTML 크롤링 파싱 후 메타데이터(`collected_at`, `method`, `source_name`)를 추가하여 JSONL로 append 저장[cite: 1].
2. **정제 (`clean.py` $\rightarrow$ `sqlite_mgr.py`)**:[cite: 1]
   - HTML 태그 제거 및 불필요한 공백 정규화[cite: 1].
   - RFC822 / ISO8601 등 다변화된 날짜 문자열을 표준 `YYYY-MM-DD`로 통일[cite: 1].
   - 필수 필드(URL, 제목, 본문) 누락 기사 필터링[cite: 1].
3. **요약 및 분석 (`summarize.py`, `analyze.py`, `sentiment.py`)**:[cite: 1]
   - `clean_news`에서 미요약(`is_summarized=0`)기사를 조회하여 AI 3줄 요약 업데이트 (`is_summarized=1`)[cite: 1].
   - 기간/카테고리 조건을 그룹핑하여 AI 인사이트 도출 후 `ai_insight` 테이블에 Upsert[cite: 1].
   - 감성 분석 결과를 `sentiment` 및 `sentiment_reason` 컬럼에 저장[cite: 1].
4. **리포팅 및 내보내기 (`report.py`, `export.py`)**:[cite: 1]
   - SQL 집계(`COUNT(*)`, `GROUP BY`)를 활용하여 정제 통과율, 요약 성공률, TOP N 키워드/카테고리 도출[cite: 1].
   - CSV, JSONL, Excel 파일 내보내기 수행[cite: 1].

## 5. 중복 처리 및 인덱싱 전략 (Deduplication & Indexing)

### 5.1 중복 처리 정책 로직

- **`news_id` 기준**: 기사의 원본 주소(URL)를 PK로 사용하여 중복 판단 기준 설정[cite: 1].
- **`skip` 정책**: DB 사전 조회(`get_by_news_id`)를 통해 이미 존재하는 `news_id` 항목은 정제 대상에서 건너뜀[cite: 1].
- **`upsert` 정책**: SQLite `INSERT ... ON CONFLICT(news_id) DO UPDATE` 구문을 사용하여 제목과 본문을 최신 정제 데이터로 Update[cite: 1].

### 5.2 인덱싱 설계 사유

- **`idx_clean_news_category`**: `--category` 옵션 검색 시 전수 스캔(Full Scan) 방지[cite: 1].
- **`idx_clean_news_pub_date`**: `--date-from`, `--date-to` 기간 필터링 쿼리 속도 보장[cite: 1].
- **`idx_clean_news_is_summarized`**: `summarize --unsummarized` 배치 처리 시 미요약 대상 고속 추출[cite: 1].
