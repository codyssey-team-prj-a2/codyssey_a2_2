# DB 구조 정의서

## 설계 개요

JSONL + SQLite 하이브리드 설계 이유

1. 수집 단계 (Raw Data) 👉 JSONL
   - 유연한 수용: 언론사마다 제각각인 원본 데이터를 구조(스키마) 고민 없이 그대로 저장

   - 원본 보호: 수정 없이 빠르고 안전하게 이어 붙여(Append) 원본 훼손 방지

2. 분석 단계 (Clean & Insight) 👉 SQLite
   - 쉬운 업데이트: SQL 쿼리로 복잡한 중복 방지와 덮어쓰기(Upsert)를 한 번에 해결

   - 강력한 집계: 인덱스(Index) 기반의 고속 검색과 통계(TOP N) 연산 최적화

3. 왜 두 가지를 모두 썼는가? (Why Hybrid?)
   - "적재적소의 기술 배치"

   - 수집의 유연성(JSONL)과 분석의 효율성(SQLite)이라는 두 마리 토끼를 모두 잡아, 실무 데이터 파이프라인의 모범 구조를 어필하기 위함.

### 별첨 - 구조정의의 상세사유

[설계 방향] 하이브리드 데이터 저장소 설계 전략 본 프로젝트는 수집된 데이터를 영구 저장소로 관리하기 위해 JSONL(JSON Lines)과 SQLite를 병행하여 사용하는 ‘하이브리드 저장소 아키텍처(Hybrid Storage Architecture)’를 채택했습니다.

단일 저장 방식을 고집하기보다, 데이터의 생애 주기(Data Lifecycle)와 각 단계별 요구사항에 가장 적합한 기술을 매핑하여 파이프라인의 성능과 유연성을 극대화했습니다.

1. Raw Data : JSONL

- 외부 뉴스 API나 크롤링을 통해 수집된 최초의 데이터(Raw Data)는 '무결성 보장'과 '빠른 적재(Append-only)'가 최우선 목표입니다.

- 스키마리스(Schemaless)의 유연성: 각 언론사나 RSS 피드마다 제공하는 데이터 필드(태그)의 규격이 다릅니다. JSONL은 사전 정의된 스키마 없이, 들어오는 형태 그대로(As-is) 데이터를 받아낼 수 있어 수집 단계의 병목을 없앱니다.

- 순차 쓰기 성능과 백업: 원본 데이터를 훼손 없이 파일 끝에 이어 붙이기만 하면 되므로 기록 속도가 매우 빠르며, 파이프라인 하단에 오류가 생기더라도 원본 데이터를 안전하게 보존하는 영구 백업(Archive) 역할을 수행합니다.

2. Clean & Insight 계층: 왜 SQLite로 전환했는가?

- 정제(Clean) 단계를 거친 데이터는 단순 저장을 넘어, '검색', '업데이트', '통계 집계'라는 비즈니스 로직의 핵심 재료로 사용됩니다.

- 강력한 트랜잭션과 Upsert: 요구사항인 '중복 데이터 방지 정책(skip/upsert)'을 JSONL로 구현하면 전체 파일을 다시 읽고 써야 하는 극심한 비효율이 발생합니다. SQLite의 INSERT ON CONFLICT 구문을 활용하여 데이터 충돌과 업데이트를 완벽하고 우아하게 처리했습니다.

- 인덱스(Index) 기반의 고속 필터링: 사용자가 CLI에서 입력한 특정 카테고리와 기간(Date Range) 조건을 즉시 필터링하기 위해, SQLite에 인덱스를 구축하여 데이터가 방대해져도 0.01초 단위의 일관된 조회 성능을 보장합니다.

- 복잡한 통계 집계 연산 (TOP N): 비즈니스 리포팅을 위한 품질 지표 계산과 TOP N 추출 시, 파이썬 메모리에 의존하지 않고 SQL의 강력한 그룹핑(GROUP BY)과 정렬 연산을 활용하여 리소스를 획기적으로 절약했습니다.

💡 결론:

```두 기술을 혼합한 이유 (Why Hybrid?)
"데이터 엔지니어링의 본질은 **'적재적소(Right tool for the right job)'**에 있습니다."

모든 데이터를 JSONL로 처리했다면 조회와 업데이트 단계에서 심각한 병목(Bottleneck)이 발생했을 것이며, 반대로 처음부터 SQLite를 강제했다면 다양한 형태의 외부 데이터(Raw)를 수용하는 유연성이 떨어졌을 것입니다.

우리는 JSONL의 유연함(Flexibility)으로 원본을 수집하고, SQLite의 관계형 구조(Relational)로 데이터를 가공·분석함으로써, 확장 가능하고 견고한 데이터 파이프라인의 모범 사례를 구현했습니다.
```
