# 시스템 아키텍처 및 모듈 설계서 (System Architecture & Module Design)

- **프로젝트명**: Python CLI 기반 AI 뉴스 데이터 파이프라인 & 인사이트 리포트 자동화 서비스
- **대상 레포지토리**: `codyssey-team-prj-a2/codyssey_a2_2` (`main` 브랜치)
- **문서 버전**: v1.0.0
- **작성일**: 2026-08-14

---

## 1. 개요 (Overview)

### 1.1 목적

본 문서는 제공된 소스코드 및 파일 구조를 바탕으로 본 시스템의 계층 아키텍처, 디렉토리 및 모듈 구조, 컴포넌트 간 데이터 흐름, 팀 R&R(역할 분담) 및 배포 파이프라인 구조를 기술적으로 명세한다.

### 1.2 아키텍처 설계 원칙

1. **단일 라우터 진입점 (`src/main.py`)**: 단일 파일에서 TUI 대화형 메뉴와 각 모듈별 CLI 서브커맨드 직접 실행 모드를 동시에 분기 처리한다.
2. **관심사 분리 및 모듈화**: `lib/system`, `lib/db`, `lib/common`, `lib/dev`로 모듈을 격리하여 수집·정제·AI·리포팅·저장소 간 독립성을 보장한다.
3. **하이브리드 저장소 (Hybrid Storage)**: 수집 원본의 유연한 append 적재를 위한 **JSONL(Raw)**과, 빠른 검색/Upsert/집계 연산을 위한 **SQLite(Clean)**를 혼용한다.
4. **컨테이너화된 격리 환경**: `docker/Dockerfile` 및 `docker-compose.yml`을 통해 개발 및 실행 환경의 동일성을 유지한다.

## 2. 전체 시스템 아키텍처 (System Architecture)

- **User & Execution Layer**:
  - `src/main.py`: TUI 메인 라우터 (`run_tui()`) 및 모듈별 `run_menu_show()` 호출
  - `lib/system/ui.py`: 터미널 UI 렌더링, 화면 제어 및 사용자 입출력 제어
- **Pipeline & Service Layer (`src/lib/dev/`)**:
  - `setup.py`: AI 플랫폼, 뉴스 소스, DB/로그 경로 환경 설정
  - `fetch.py`: RSS 피드 파싱(`feedparser`) 및 크롤링(`beautifulsoup4`)
  - `clean.py`: HTML 태그 정제, 날짜 정규화 및 `skip`/`upsert` 정제
  - `summarize.py`: AI 3줄 요약 수행 및 DB 반영
  - `analyze.py`: 지정 기간/카테고리 종합 AI 인사이트(트렌드/키워드/시사점) 도출
  - `report.py`: Matplotlib 시각화 차트(PNG) 생성, 품질 지표 및 Top N 집계, 콘솔/TXT/MD 리포트
  - `export.py`: Clean 데이터의 CSV/JSONL/Excel 파일 내보내기
  - `list_news.py` / `show.py`: 뉴스 목록 페이징 및 상세 조회
  - `sentiment.py`: AI 기반 뉴스 감성(긍정/부정/중립) 분석
- **Common & Data Layer (`src/lib/common/`, `src/lib/db/`)**:
  - `ai_client.py`: Multi-LLM (Gemini, OpenAI, Anthropic) 공통 wrapper
  - `raw_store.py`: JSONL 파일 생성 및 append/read
  - `sqlite_mgr.py` & `schema.sql`: SQLite DB 연결, 테이블 생성, DDL 마이그레이션 및 DAO 쿼리
- **Infrastructure Layer**:
  - `docker/`: Dockerfile, docker-compose.yml (`codyssey_pipeline` 컨테이너)

## 3. 개발 및 배포 워크플로우 (Development & Deployment Pipeline)

1. **개인 Developer Repository (`dev-*`)**
   - 팀원별 모듈 단위 개발 및 개별 커밋
2. **Staging Repository / Branch (`staging`)**
   - 최신 코드 동기화 및 Docker 환경 기반 단위 테스트 (Unit Test) 수행
3. **Main Repository / Branch (`main`)**
   - 전체 파이프라인 관통 E2E 통합 라이브 테스트 (Integration Test) 검증 및 최종 제출

## 5. 모듈별 역할 및 모듈 관점 R&R 명세 (Module Specifications & R&R)

### 5.1 프로젝트 관리 및 인프라 (PM: 박순몽)

- 일정 및 설계 제어: WBS, 간트 차트, 프로젝트 설계 전략 수립 및 이슈 생성(script/create_issue.sh).

- src/main.py: 라우터 모듈 (MODULE_MAP을 통한 1~10 번호 매핑 및 실행 분기).

- src/lib/system/: config_mgr.py (src/config.json 및 .env 파일 관리), ui.py (터미널 렌더링).

- src/lib/db/: raw_store.py (JSONL 조작), schema.sql (DDL), sqlite_mgr.py (SQLite Connection & DAO).

- docker/: Dockerfile, docker-compose.yml, run.sh (컨테이너 오케스트레이션).

### 5.2 모듈 개발 (Developers: 김병국, 이원일)

- src/lib/common/ai_client.py: Gemini (google-genai), OpenAI (requests 직접 통신), Anthropic (anthropic) Multi-LLM 연동 및 재시도 백오프 로직 구현.

- src/lib/dev/:
  - setup.py: 환경 설정 UI 로직.

  - fetch.py: RSS (feedparser) 및 크롤링 (BeautifulSoup) 수집기.

  - clean.py: Raw 데이터 읽기, 정규화, 중복 체크 및 SQLite 저장.
    - summarize.py: is_summarized=0 대상 3줄 요약 실행.

    - analyze.py: 종합 트렌드, 키워드, 시사점 추출 및 ai_insight 적재.

    - report.py: Matplotlib 시각화 차트 생성, 품질 지표 및 Top N 집계, 파일 출력.

    - export.py: CSV, JSONL, Excel 파일 출력.

    - list_news.py / show.py / sentiment.py: 페이징 조회, 상세 보기, 감성 분석.

### 5.3 품질 보증 및 테스트 (QA: 김정진)

- 테스트 시트 관리: documentation/test/QA*체크리스트*환경설정테스트.xlsx 작성 및 검증.
- 테스트 수행: Staging 단위 테스트 및 Main 통합 E2E 테스트 주도, 예외/크래시 피드백 및 미팅록 작성.

## 6. 컴포넌트 간 데이터 흐름 (Data Flow Architecture)

- [수집 (fetch.py)]
  - 외부 RSS / 크롤링 ➔ raw_store.py ➔ ./data/raw/{source_name}.jsonl (Raw File)

- [정제 (clean.py)]
  - ./data/raw/\*.jsonl ➔ sqlite_mgr.py ➔ SQLite DB (clean_news 테이블)

- [AI 분석 (summarize.py / analyze.py / sentiment.py)]
  - clean_news 테이블 ➔ ai_client.py (LLM SDK) ➔ SQLite DB (clean_news / ai_insight 테이블)

- [시각화 & 출력 (report.py / export.py)]
  - clean_news / ai_insight ➔ Matplotlib (PNG 차트) / 파일 생성 (TXT, MD, CSV, Excel, JSONL)

## 7. 예외 처리 및 하이브리드 바인딩 아키텍처

1. 설정 동적 바인딩: config_mgr.py가 SRC_DIR / "config.json" 및 SRC_DIR / ".env" 경로를 직접 참조하여 실행 위치에 독립적인 경로 제공.

2. LLM 통신 예외 방어: ai_client.py에서 HTTP Status Code(429, 5xx) 발생 시 지수 백오프(Exponential Backoff) 기반 재시도(기본 5회) 수행 및 Gemini thinking_budget=0 지정을 통한 답변 자름 방지.

3. SQLite 마이그레이션: sqlite_mgr.py 내 \_migrate_schema()를 통해 기존 DB 파일 존재 시에도 신규 컬럼(sentiment, sentiment_reason)을 PRAGMA로 자동 동기화.
