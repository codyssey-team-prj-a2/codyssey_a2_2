# 실행 결과 보고서

## 개요

`src/main.py` 기반 파이프라인(fetch → clean → report → export)을 실제 외부 데이터로 end-to-end 실행한 결과입니다.
실행 환경: Windows, Python, `src/config.json`에 등록된 뉴스 소스 4건 기준.
AI API 키(`LLM_API_KEY`)가 로컬에 설정되어 있지 않아, AI 연동이 필요한 summarize/analyze/sentiment 단계는 이번 실행에서 제외했습니다.

## 1. 뉴스 수집 (fetch)

`fetch --source all --limit 20` 실행 결과:

| 소스 | 방식 | 결과 |
| --- | --- | --- |
| google_news_it_rss | RSS | 20건 추출 성공 |
| hackernews_api | API | 건너뜀 (`api` 수집 방식 미구현) |
| wikipedia_current_events_crawl | 크롤링 | 9건 추출 성공 |
| ArXiv_cs.AI | RSS | 20건 추출 성공 |

- 총 추출: **49건**, 실패: 0건
- raw 데이터는 `data/raw/{source_name}.jsonl`에 저장

## 2. 데이터 정제 (clean)

`clean --policy upsert` 실행 결과:

| 항목 | 값 |
| --- | --- |
| raw 전체 | 49건 |
| 필수 필드 누락 제외 | 0건 |
| 중복 URL(news_id) 정제 병합 | 2건 (위키백과 크롤링 결과 중 동일 URL 2쌍) |
| clean_news 저장 | **47건** |

## 3. 품질 지표 (report)

| 지표 | 값 |
| --- | --- |
| ① 데이터 정제 통과율 | raw 49건 → clean 47건 = **95.92%** |
| ② AI 요약 성공률 | 시도 대상 47건 중 성공 0건 = 0.0% (API 키 미설정으로 summarize 미실행) |

## 5. 시각화 차트 (report)

`reports/charts/`에 PNG로 생성 확인 (빌드 산출물이라 `.gitignore`로 저장소에는 포함하지 않음):

- `category_distribution.png` — 카테고리별 뉴스 건수 막대 차트
- `daily_trend.png` — 일자별 수집 추이 꺾은선 차트
- `sentiment_distribution.png` — 감성 분포 원형 차트 (감성 분석 데이터 없어 빈 차트)

## 6. 내보내기 (export)

`export --format [csv|excel|jsonl] --status all` 각각 실행, clean_news 47건 전체 정상 저장 확인:

| 포맷 | 결과 |
| --- | --- |
| CSV | 47건, UTF-8(BOM) 저장 완료 |
| Excel(xlsx) | 47건, pandas/openpyxl 저장 완료 |
| JSONL | 47건, 라인 단위 UTF-8 저장 완료 |

## 결론 / 남은 작업

- fetch(RSS/크롤링) → clean → report(품질 지표/TOP N/차트) → export 파이프라인이 실제 외부 데이터로 정상 동작함을 확인했습니다.
- `hackernews_api` 소스는 `api` 수집 방식이 아직 구현되지 않아 건너뛰었습니다 — 구현 시 `fetch.py`의 `FETCH_HANDLERS`에 핸들러 추가가 필요합니다.
- summarize/analyze/sentiment(AI 연동 단계)는 `LLM_API_KEY` 설정 후 재검증이 필요합니다.
