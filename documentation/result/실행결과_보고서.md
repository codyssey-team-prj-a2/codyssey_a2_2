# 실행 결과 보고서

`src/main.py` 파이프라인(fetch → clean → report → export)을 실제 외부 뉴스 데이터로 end-to-end 실행한 로그입니다.
아래 로그는 실제 실행 결과를 그대로 옮긴 것이며(문구를 지어내지 않음), 현재 CLI는 각 기능의 서브메뉴 안에서
명령어를 입력하는 방식이라 프롬프트는 `Codyssey/<모듈명> >` 형태입니다.

실행 환경: Windows / Python, `src/config.json`에 등록된 뉴스 소스 기준.
로컬에 `LLM_API_KEY`가 설정되어 있지 않아, AI 연동이 필요한 summarize/analyze/sentiment는 이번 실행 로그에 포함하지 않았습니다(아래 5절 참고).

## 1. 뉴스 수집 (fetch)

```
Codyssey/fetch > fetch --source google_news_it_rss --limit 20

>> [CLI 모드] 뉴스 데이터 수집을 시작합니다...
   (적용 옵션: source=google_news_it_rss, limit=20)

  [수집 진행] google_news_it_rss (RSS) 데이터 요청 중...
    - [SBA x IT동아] 한국시니어연구소 "스마일 시니어는 보호자-사업자 함께 웃는 요양 플랫폼" - 동아일보
    - 삼성·LGD 새 성장축은 'IT'…애플 맥북·아이맥 OLED 적용 기대 - 지디넷코리아
    - 中 IT업계 유명한 '996' 근무…美 빅테크는 주 7일 90시간 일했다 - 중앙일보
    ... (총 20건)
  └─ [google_news_it_rss] 20건 추출 및 raw 저장 완료

>> 수집 작업이 완료되었습니다! (총 20건 추출, 실패 0건)
```

이어서 나머지 등록 소스도 동일하게 수집했습니다.

```
Codyssey/fetch > fetch --source wikipedia_current_events_crawl --limit 20
>> 수집 작업이 완료되었습니다! (총 9건 추출, 실패 0건)

Codyssey/fetch > fetch --source ArXiv_cs.AI --limit 20
>> 수집 작업이 완료되었습니다! (총 20건 추출, 실패 0건)
```

| 소스 | 방식 | 결과 |
| --- | --- | --- |
| google_news_it_rss | RSS | 20건 성공, 0건 실패 |
| wikipedia_current_events_crawl | 크롤링 | 9건 성공, 0건 실패 |
| ArXiv_cs.AI | RSS | 20건 성공, 0건 실패 |
| hackernews_api | API | 건너뜀 (`api` 수집 방식 미구현) |

- 총 수집: **49건 성공, 0건 실패**
- raw 저장소(`data/raw/{source_name}.jsonl`)에 저장 완료

## 2. 데이터 정제 (clean)

```
Codyssey/clean > clean --policy upsert

[ 정제 결과 (정책: upsert) ]
  - raw 전체: 49건
  - 필수 필드 누락(제외): 0건
  - 중복 스킵: 0건
  - DB 저장(신규/갱신): 49건
```

`upsert` 정책에서는 중복 URL(news_id)도 스킵하지 않고 그대로 덮어써 저장하기 때문에,
raw 49건이 clean_news 테이블에 upsert된 뒤 news_id(PK) 기준으로 자동 병합되어 실제 저장된 고유 레코드는 **47건**입니다
(위키백과 크롤링 결과 중 동일 URL 2쌍이 병합됨. DB 조회로 재확인: `SELECT COUNT(*) FROM clean_news` → 47).

```
Codyssey/report > report --format console

============================================================
                 코디세이 뉴스 데이터 분석 리포트
============================================================
생성 시각: 2026-08-13 17:43:53
집계 기간: 전체 기간
------------------------------------------------------------
[ 품질 지표 ]
  ① 데이터 정제 통과율: raw 49건 → clean 47건 = 95.92%
  ② AI 요약 성공률   : 시도 대상 47건 중 성공 0건 = 0.0%
------------------------------------------------------------
[ TOP N 집계 ]
  최다 출현 핵심 키워드 TOP 5
    집계할 ai_insight 데이터가 없습니다.
  카테고리별 뉴스 수집량 TOP 3
    1. AI (20건)
    2. IT (20건)
    3. 종합 (7건)
============================================================
```

- AI 요약 성공률이 0%인 이유: `LLM_API_KEY` 미설정으로 summarize 단계를 실행하지 않았기 때문(아래 5절)
- 핵심 키워드 TOP5가 비어있는 이유: `ai_insight` 테이블은 analyze 단계 산출물인데, 역시 AI 키 미설정으로 미실행

`report --format md` / `report 7`(감성 분포 차트) 실행 시 `reports/` 아래에 다음 파일이 실제로 생성되는 것도 확인했습니다
(빌드 산출물이므로 `.gitignore`로 저장소에는 포함하지 않음):
- `reports/charts/category_distribution.png`
- `reports/charts/daily_trend.png`

## 5. AI 연동 단계(summarize / analyze / sentiment) — 미실행

로컬 환경에 `LLM_API_KEY`가 설정되어 있지 않아 아래 3개 명령은 이번 실행에서 **실제로 돌리지 않았습니다**.
실행하면 다음 형태의 명령이 되며, 키 설정 후 재검증이 필요합니다.

```
Codyssey/summarize > summarize --unsummarized --limit 10
Codyssey/analyze   > analyze --date-from 2026-08-01 --date-to 2026-08-13 --category IT
Codyssey/sentiment > sentiment --unanalyzed --limit 10
```

(참고: `summarize`/`analyze`는 담당자가 실제 API 키로 실행 및 결과 확인 후, 이 문서 또는 별도 결과 문서에
`[INFO] [1/10] ID=... 요약 완료 (...자 → ...자)` 같은 실제 로그를 추가하는 것을 권장합니다. 가짜 출력을 기록하지 않기 위해
이번 보고서에는 포함하지 않았습니다.)

## 결론 / 남은 작업

- fetch(RSS/크롤링) → clean → report(품질 지표/TOP N/차트) → export 파이프라인이 실제 외부 데이터로 정상 동작함을 확인했습니다.
- `hackernews_api` 소스는 `api` 수집 방식이 아직 구현되지 않아 건너뛰었습니다 — 구현 시 `fetch.py`의 `FETCH_HANDLERS`에 핸들러 추가가 필요합니다.
- summarize/analyze/sentiment(AI 연동 단계)는 `LLM_API_KEY` 설정 후 실제 실행 로그로 재검증이 필요합니다.
